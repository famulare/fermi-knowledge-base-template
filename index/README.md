# Index Layer

**Purpose:** Semantic organization and retrieval acceleration

**Status:** Generated and maintained by Fermi (regenerable from canonical sources)

---

## Architecture

The index layer uses a **two-tier retrieval** architecture:

### Tier 1: Router (always loaded at session start)

- **`router.md`** — Compact domain map with file inventory and section inventories
  for large files. Generated by `scripts/generate_router.py`. Target: ~10K tokens.
- **`RETRIEVAL_RECIPE.md`** — Canonical procedure for query resolution.

### Tier 2: Detailed indices (loaded on demand)

- **`tags.md`** — High-signal tags with file associations
- **`entities.md`** — Named entities with canonical aliases
- **`link_graph.md`** — Structurally meaningful links between KB elements
- **`glossary.md`** — Domain-specific term definitions

Tier 2 files are loaded **only when the router is insufficient** for candidate
identification in a query.

---

## Principle

All index files are **derived artifacts** — regenerable from the markdown corpus
(`raw/`, `meta/`, etc.). If any file is corrupted or lost, it can be regenerated.

The markdown corpus is the canonical source of truth. The index is an acceleration
layer, not an authority.

---

## Regeneration

```bash
uv run scripts/generate_router.py     # Regenerate router.md from corpus
uv run scripts/kb_search.py rebuild   # Rebuild SQLite FTS5 index (when available)
```

---

## Tagging Philosophy

Tags should reveal **structural connections**, not exhaustive categorization.

Good tags: mechanisms, cross-domain patterns, conceptual frameworks.
Poor tags: generic topics, date-based categories, redundant labels.

Prefer 20-50 high-signal tags over exhaustive categorization.
